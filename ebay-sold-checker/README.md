# eBay Sold Checker (Japanese character goods, batch)

Checks eBay sold listings for a wide catalog of Japanese character-goods
queries (e.g. "Gojo Satoru peluche", "Tanjiro figurine") and produces a
sortable, filterable report.

## What it does

- Catalog: `queries.csv` / `queries.yaml` — 800 queries generated by
  `make_catalog.py`: 100 characters across 30 franchises x 8 goods types
  (peluche, figurine, porte-clés, badge, stand acrylique, gashapon,
  poupée, magnet).
- For each query: runs the proven flow against one marketplace —
  Chrome-TLS (curl_cffi) session through your proxy, seeded with your
  verified cookie export, silent login only as a fallback (max ONE login
  attempt per run: repeated logins can trigger eBay account step-up
  verification), sold search, eBay's own next-page links (1-4 pages),
  locale-aware parsing with batch-signature counting.
- Output: `results.db` (SQLite, resumable — re-running skips already-done
  queries), `results.csv` and `report.html` (click column headers to sort,
  free-text filter, franchise/goods dropdowns, min-sold filter).

## Usage

```bash
pip install curl_cffi
export EBAY_PROXY="http://user:pass@host:port"   # optional but recommended
export EBAY_EMAIL="..." EBAY_PASSWORD="..."       # login fallback only
cp cookies_ebay_fr.json .                         # EditThisCookie export, one per marketplace

python3 checker.py --list queries.csv --limit 20      # first 20 queries
python3 checker.py --list queries.csv --start 20      # resume / continue
python3 checker.py --list queries.csv --delay 12      # polite batch (default 10s)
python3 checker.py --report-only                      # rebuild csv + html from db
```

Full sweep: 800 queries x (1-2 pages + delay) = several hours; run in
chunks (`--start/--limit`) overnight. All flags: `--pages 1..4`,
`--marketplace fr`, `--redo-failed`.

## Requirements / troubleshooting

- A **valid eBay session** for the marketplace, exported from your own
  logged-in Chrome (EditThisCookie JSON). Sessions last a few hours; export
  fresh before long runs. Without a valid session the sold search serves
  eBay's sign-in wall, and the login fallback triggers at most once.
- If eBay shows account "step-up" verification (Accès au compte / Seller
  Hub hub), log in once manually in your own Chrome and complete the
  verification - it is account protection, not a bug. Then re-export
  cookies.
- Rate: keep `--delay` >= 10s for long batches; the verified session is a
  perishable asset.

## Files

- `make_catalog.py` - edit the character roster/franchises/goods types and
  regenerate `queries.csv` + `queries.yaml`
- `checker.py` - batch runner + report generator
- `result_state`: `results.db` is created on first run
